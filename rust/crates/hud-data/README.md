# HUD data migration slice

This crate provides pure agenda operations and an explicit read-only Vault snapshot. It does not read any personal configuration automatically, write files implicitly, follow symlinks, start processes, or start background threads. Pass a root explicitly to `scan(root, term, Limits)`.

The `Agenda` model parses and serializes Python-compatible Markdown lines, supports Portuguese date/time entry, add/remove/done/prune, pending ordering and day labels. The caller supplies today's date; there is no hidden timezone or clock assumption. Gregorian dates are validated. Unicode text is truncated by characters. Display cleaning removes escape sequences, control/bidi characters; `display_rel`/`display_source` sanitize paths while raw paths remain identifiers.

The POSIX scanner opens every root component and descendant relative to pinned directory descriptors with `NOFOLLOW`, and each note with `NONBLOCK`. The opened note must be a regular file, match checked device/inode, belong to the current UID, and remain within the read cap (limit+1 read). It skips hidden names, build/dependency directories, non-notes and symlinks. It parses Obsidian Kanban columns, pending due tasks, conflict names and literal case-insensitive search. Default caps: 2 MiB/note, 50,000 notes, 64 levels, 64 MiB total, 40 search hits; an additional entries cap bounds directory-only trees. Results are deterministic by directory filename ordering.

Current-user ownership of opened notes is stricter than Python `hud/vault.py`, which validates type/identity/size but has no UID restriction. Vault directories and ancestors need not be private or owned by this user because scanning does not write them. Descriptor pinning prevents symlink redirection, but cannot stop an authorized actor moving an already-open directory or modifying the contents of the same open inode. No full snapshot isolation is claimed.

Verified reference: `hud/agenda.py` (Item/date/time/entry/Markdown/upcoming/prune/labels), `hud/vault.py` (Board/Snapshot/parse_board/parse_tasks/read_note/search) and `hud/text.py` (clean/strip_markdown), inspected in the local Python checkout. This is a bounded initial implementation, not full Python parity.

Remaining: watcher thread/cache/refresh/root switches, recent/today/Obsidian statistics, exact complete Python regex and text-cleaning edge cases, note editing/actions and Windows adapter. Non-Unix scanning returns Unsupported. macOS compilation was not tested. Integration must sanitize all externally derived paths before display, including conflict strings.

`AgendaStore`/`FileAgendaStore` add opt-in POSIX storage in an explicit private directory, separate file `agenda.md`. Load is bounded to 256 KiB / 2,048 items; missing load does not create directories. The final directory/file must be current-user owned and private (0700/0600); ancestors cannot be writable by others except sticky directories. Each component is pinned with NOFOLLOW. Save validates local items before creating anything, writes an exclusive private temporary, syncs data, atomically renames and syncs the directory. No source-marked Vault item is accepted into local storage. Invalid UTF-8, malformed task lines, limits, non-private files, symlinks and FIFO fail closed. Comments/prose tolerated by Python input are not preserved when saving: serialization rewrites the canonical agenda document. Invalid stored clock values are rejected, stricter than Python's load regex.

Save failures before rename preserve the old file and clean the temporary. Directory fsync can fail after rename, so an error at that stage may mean the new file is visible but durability is unconfirmed. The application must report this ambiguity and reload to reconcile before assuming rollback. Pinning cannot stop the same UID moving the opened directory. Non-Unix agenda storage returns Unsupported without writing.

Linux verification: `cargo test --locked --offline`, `cargo clippy --locked --offline --all-targets -- -D warnings`, `cargo fmt --check`. Fixture tests cover dates/time/Unicode, agenda round trips and pure operations, Kanban/due parsing, terminal control stripping, read-only scanning, root/note symlinks, regular-inode replacement races, symlink replacement races, FIFO, depth and size/volume/count bounds, private agenda round trips, UTF-8/malformed/oversize rejection, atomic replacement, deterministic pre-rename failure recovery and temporary cleanup. No active Vault was used for tests.

## Incremental scanner, local calendar and explicit note actions

`ScanCache` plus `scan_cached` cache bounded parsed entries and shared note text. Each scan still enumerates and opens every candidate with existing descriptor/UID/type checks; cache keys include device, inode, UID, size, mtime/nanoseconds and ctime/nanoseconds. Stable files skip reading/parsing; changed, moved, deleted or newly limited entries are rebuilt/evicted. Reads check metadata again after bounded read. A successful scan replaces the cache; cancellation/failure retains the previous cache. Source text storage is capped to `Limits.total_bytes`, file count and total-read caps still apply, and returned snapshot has separate bounded parsed data. Metadata caching cannot detect hostile same-inode modifications with indistinguishable metadata, or mutations just after validation; snapshot isolation is not claimed.

`Snapshot` now exposes `today`, the twelve most recent accepted notes with Unix timestamps, `.obsidian` directory detection, `reads` and `cache_hits`. Filters include `boards_matching`, `tasks_on(Date)` and sanitized `recent_matching`. Owner/size-rejected notes are omitted from recent/today, unlike Python which includes metadata for oversized notes before parsing. Conflict notes retain their pre-read metadata counting behavior. Searching unchanged notes uses the cached full text, preserving the previous first-content-hit-per-note semantics and hit limit.

`CalendarClock` separates host-local calendar boundaries from monotonic UI refresh. `SystemLocalClock` uses already-locked libc 0.2.190 with a small audited `localtime_r`/`mktime` boundary and recalculates DST at midnight (`tm_isdst=-1`); no shell/process/TZ mutation is used. `FakeClock` supplies local day/midnight/now in tests; `VaultController::with_clock` injects it. Non-Unix local conversion honestly returns Unsupported. Tests simulate 23h/25h local days and validate the current Linux host's native conversion round trip; actual non-UTC/DST timezone transitions were not exercised natively. The process timezone must remain stable while conversions run.

`NoteStore` is opt-in per explicit root. `preview_read` returns raw bytes plus sanitized display without launching an editor or writing. `preview_toggle(rel, one_based_line, done)` builds a checkbox-only byte proposal while preserving all remaining UTF-8/CRLF/wikilinks/aliases/manual prose. `apply_toggle` is a distinct explicit approval operation: before opening a private exclusive temporary and again before rename it checks note identity/timestamps/mode/owner, complete directory-chain identity and exact original bytes. Immediately before commit it reopens the selected root/relative chain and compares all directory device/inode identities, so a directory moved away during temporary writes is refused. It pins directories and uses NOFOLLOW/NONBLOCK, refuses paths outside the selected root, hidden components, non-note files, symlinks, FIFO, foreign-owned files and group/other-writable note or destination directory. Source notes may be group-readable. It preserves original permission bits, syncs the temporary, atomically replaces the note and syncs the directory. Unchanged previews are not reusable after replacement.

This is optimistic concurrency checking, **not a filesystem atomic compare-and-swap**: an actor able to modify the same directory can race the final check-to-rename interval or move an open directory. A directory fsync error after rename can mean content committed but durability is unknown; callers must reload/reconcile and must not claim rollback. Before-rename failure keeps manual bytes and removes temporary files. Only fixture roots were modified; read/open means reading the selected note, never opening GUI/external editors. No complete arbitrary-note editing or task grammar parity is claimed.
