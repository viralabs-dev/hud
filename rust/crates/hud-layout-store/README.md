# Secure Rust layout state (AT-069, partial platform acceptance)

`FileLayoutStore::new(explicit_state_dir, max_columns)` implements `LayoutStore` with `load() -> io::Result<Option<Layout>>` and `save(&Layout) -> io::Result<()>`. File name is `layout.state`; codec is HUD-LAYOUT 1, not Python TOML. Application must supply a separate Rust namespace, e.g. `--state-dir`; there is no environment/default-path guessing in this adapter.

POSIX: every path component is opened relative to a pinned descriptor with DIRECTORY/NOFOLLOW. Parent traversal is rejected. Missing final directory is created with mode700; ancestors must exist. Shared sticky ancestors such as /tmp are allowed; nonsticky group/other-writable ancestors are refused. Namespace and state must be current-user-owned and have no group/other permission. Reads validate regular-file type and size before a bounded MAX_BYTES+1 read. Save validates codec/column limits before mutation, refuses preexisting nonregular/public/foreign destination, uses create-exclusive private temp, syncs contents, descriptor-relative atomic rename and directory fsync. Failed pre-rename operations remove the temporary file. A post-rename fsync failure returns an error even though the new file can already be visible; callers must not falsely claim no mutation after such failure.

Descriptor traversal pins directories rather than repeatedly resolving absolute names; symlink replacement cannot redirect an already opened descriptor. This is not sandboxing against arbitrary code running as the same user and mutating directory topology. No Python data/import/trust migration is implemented. Same-user concurrent saves use distinct temp names and last successful rename wins; concurrent editing/merge is outside this adapter contract.

Windows/non-POSIX load/save return Unsupported without filesystem mutation. Do not mark cross-platform AT-069 complete. Need native Windows handle/reparse containment implementation and tests; macOS POSIX compilation/execution also remains unverified here.

Validation performed with Rust/Cargo1.99 on Linux: 6 unit tests cover save/reload, private modes, missing-load no writes, parent/final symlinks, target preservation, oversized/corrupt/public files, invalid columns no directory creation, parent traversal and atomic replacement retaining old-reader contents. `cargo clippy --offline --all-targets -- -D warnings` passed. Isolated test dependencies used temporary copies of domain/codec, with domain package name matching integrated `hud-domain`; production Cargo.lock is integration-owned. Tests do not prove physical mouse or Windows behavior. Application owns cancellation/no-save policy.

Dependency: official registry rustix exactly1.1.5 (MIT OR Apache-2.0); fs and process features. process supplies current UID for ownership validation. No system package installation was performed by this task.
