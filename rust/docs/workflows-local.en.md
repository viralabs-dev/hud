Current installed 0.10.0-preview.12 is documented in [local preview](local-preview.en.md). Historical source/config remain separately preserved as explicit fallback hud-python, not target runtime. Recorded counts describe a specific tested artifact, never imply full functional parity.

Skills/projects prepare complete bounded prompts for distinct approval. Explicit agent settings/context apply to enabled tabs; provider/profile/folder transitions prepare adapters and scopes before committing remembered folder state. Followers change folder; fixed providers retain theirs; this choice is session state. Changing relevant context/profile revokes old confirmation/resume where necessary. Unknown or oversized fields fail rather than silently truncate.

Custom/file/command/document/config proposals follow preview → distinct create/overwrite/apply approval. Escape/discard cancels without writing. Saving/reloading never launches feeds or commands; command feeds need separate exact-config trust. Receipt-backed rollback compares bytes/identity and refuses manual edits or incomplete recovery. See [review workflows](review-workflows.en.md).

Production and fake backends are distinct capabilities. Metadata-only PATH candidates are inventoried in a bounded background worker; this does not verify version/auth or authorize launch. Installed wrapper selects a prepared manifest; startup does not call providers. `/agentes` shows each provider's readiness; `agent detect` has its own review/approval, and prompt approval remains separate. Unknown auth/billing/configuration and unsupported Full subscription paths stay blocked. [Real launcher gates](real-launcher.en.md) own provider acceptance.

Test layers: pure state/parser tests; private filesystem faults; supervised fake process/protocol tests; PTY with actual candidate/installed binary; physical terminal checklist; native platform/provider gates. PTY is a real terminal protocol session with injected events, not a physical desktop or real provider. Historical captures use synthetic data/providers and retain their own source revision. MSRV/native support are separate from Linux tests.

For every request, first reconcile the HUD Vault project and repository documentation, identify affected activity IDs/dependencies and preserve concurrent edits. Implement within authorized scope; update evidence/status according to actual work. AT-097 tracks this repository/Vault documentation reconciliation. New receipts must replace active instructions while old checkpoint evidence is clearly archived.
