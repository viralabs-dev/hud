# Monitor SQLite e metadados locais

Monitor de metadados integra a preview11 instalada; raízes/processos só por flags explícitas, sem iniciar provider nem descobrir HOME/config/credenciais. O adapter SQLite atual usa cópia privada congelada e biblioteca Linux existente. Acesso direto por VFS/descritor é protótipo separado (AT-080 bloqueada), não entregue nem necessário para afirmar o comportamento atual.

- `--monitor-opencode-db /caminho/privado/opencode.db`: nome exato, caminho absoluto, UID próprio/600, ancestrais sem symlink. Snapshot congelado de DB e WAL (até 64MiB cada), diretório temporário700/arquivos600 removidos ao terminar. Verifica fingerprints dev/inode/size/ctime/mtime nanos antes/depois e reabre fontes; qualquer mudança recusa/retém anterior. Não copia nem usa shm original; rollback journal exige checkpoint. SQLite pode criar shm apenas na cópia privada.
- Biblioteca opcional existente do Linux via caminho absoluto específico de arquitetura, canonicalizado/root-owned sem escrita de grupo/outros. Sem downloads, header/dev package ou dependência Cargo nova; outros SOs recusam o adapter. Ausência/biblioteca ABI incompleta vira erro visível sem derrubar TUI.
- Conexão read-only, trusted_schema OFF/query_only ON, tabela session normal requerida (views/virtual/schema desconhecido recusados), statements read-only, queries fixas. Só id,parent_id,directory,time_updated; NÃO SELECT title/message/data/prompt/tool contents. FFI RAII, limites SQLite (row1MiB/SQL8KiB/64cols/expr16/VDBE100k/attach0/worker0), progress callback a cada1000VM e budget2s incluindo cópia; entry/UTF8/tipos/células8KiB validados. I/O/dlopen/prepare bloqueados podem exceder budget; worker detach preserva shutdown. Janela recente1h/ordem timestamp e relógio injetável nos testes.
- `--monitor-root PRIVATE_ROOT`: filhos conhecidos codex/sessions, claude/projects e opencode/storage/session; JSON/JSONL de sessões. Não atravessa symlinks, não lê arquivos credenciais conhecidos; limites5000 entradas, profundidade5,240 sessões lidas,60 top-level e20 filhos/root. SQLite pode ser descoberto só dentro do opencode explicitamente selecionado.
- `--monitor-process-root PATH`: opcional /proc Linux ou árvore privada de fixture; só UID próprio, nomes exatos codex/claude/opencode, comm/stat limitados. Nada de cmdline/environ/cwd/conteúdo; estados de processo são amostra separada, sem afirmar liveness de sessão nem identificar todos os launchers node.

Projetos agrupados por pasta, provider/id deduplicados; filhos anexados ao ancestral conhecido, órfãos/ciclos ficam visíveis, nunca associação entre providers. Tokens/model/version vêm apenas de metadados suportados; SQLite não possui estado de execução validado e mostra Unavailable. Diferença deliberada de Python: títulos e message.data usados por hud/monitor.py:796 para inferir estado não são consultados; privacidade preservada, sem equivalência completa ou aceite físico. Estado recente não significa ativo.

Fontes técnicas oficiais: https://www.sqlite.org/c3ref/column_blob.html ; https://www.sqlite.org/c3ref/stmt_readonly.html ; https://www.sqlite.org/c3ref/progress_handler.html ; https://www.sqlite.org/c3ref/c_limit_attached.html . Mesma-UID race após último check é limite residual. Biblioteca sistema tem versão independente; nenhuma afirmação de biblioteca portátil ou bundling.
